# Meridian working rules

- Before writing or editing any report, read and apply
  [the editorial rulebook](docs/EDITORIAL-RULEBOOK.md) and
  [the analysis and evidence policy](docs/ANALYSIS-POLICY.md). This includes daily
  overviews, desk notes, reviewed article analyses and background guides in both
  languages. Apply Humanizer and the plain-language editing checks in the
  rulebook to every authored report. Faithful publisher translations retain
  their original attribution and scope.
- Reports must help the reader understand the consequences. Give a supported
  editorial assessment and concrete takeaway; research relevant named voices
  and explain substantive disagreements when the issue warrants it. Separate
  sourced facts, attributed opinion and Meridian's inference. Match the strength
  of the judgment to the evidence.
- For implementation or content changes, inspect the actual user-visible result
  and relevant adjacent paths before calling the task fixed. Distinguish source,
  generated artifacts, production state and delivery. When a defect has recurred
  or spans several workflow surfaces, read and apply
  the installed `change-closure` skill when available. Otherwise
  trace the authoritative input through all active consumers and inspect the
  resulting saved output and running interface.
- If a verification step cannot be completed, report exactly what remains
  unverified. Do not turn a passing test or an edited file into a claim that a
  production change or external delivery occurred.
